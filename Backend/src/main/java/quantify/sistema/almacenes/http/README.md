# API Testing with .http Files

This directory contains HTTP request files for testing all API endpoints of the Ferreteria Sistema Almacen application.

## Files Overview

- **auth.http** - Authentication endpoints (register, login, list users)
- **productos.http** - Product management endpoints (add, update stock, list, low stock)
- **proveedores.http** - Provider management endpoints (add, update, list)
- **salidas.http** - Product exit/delivery endpoints (register, list)

## How to Use

### Using IntelliJ IDEA / VSCode with REST Client Extension

1. Install the "REST Client" extension (for VSCode) or use IntelliJ's built-in HTTP Client
2. Open any .http file
3. Click on "Send Request" or "Run" next to any request
4. View the response in the output panel

### Using curl (Command Line)

You can convert these requests to curl commands. For example:

```bash
# Register a user
curl -X POST http://localhost:8080/auth/registrar \
  -H "Content-Type: application/json" \
  -d '{
    "nombres": "Juan Carlos",
    "apellidos": "Pérez Gutiérrez",
    "dni": "87654321",
    "email": "juan.carlos@example.com",
    "contraseña": "securePassword123"
  }'
```

## Prerequisites

- The Spring Boot application must be running on `http://localhost:8080`
- Start the application with: `./mvnw spring-boot:run` from the Backend directory

## Testing Flow Recommendations

1. Start with **auth.http**:
   - Register a new user
   - Login with that user
   - List all users

2. Then **proveedores.http**:
   - Add a new provider
   - List providers
   - Update a provider (note the ID from the list)

3. Next **productos.http**:
   - Add a new product (use the RUC from a provider)
   - List all products
   - Add stock to a product
   - Check products with low stock

4. Finally **salidas.http**:
   - Register a product exit (use employee ID and product SKU)
   - List all exits

## Notes

- All timestamps and IDs are automatically generated by the system
- Make sure to update IDs in the requests based on your actual data
- The application uses an H2 in-memory database, so data is lost on restart
- All endpoints return JSON responses
